# 2   **任务概述**

## 2.1   **背景**

瀚高全密态数据库V4.0.0已实现基础的密态数据存储、等值查询、范围查询、模糊匹配及密文索引等功能。伴随客户对密态数据库能力要求的不断提升，以及安全可靠测评对产品功能完整性的更高要求，现有版本在以下几个方面存在提升空间：

- **密文计算能力不足**  ：当前版本仅支持密文等值比较、范围比较和模糊匹配，不支持密文上的聚合运算（如SUM等），限制了密态数据库在统计分析类场景中的应用。
- **密钥管理能力有待增强**  ：当前版本不支持密钥轮换，在等保测评和安全合规评审中可能成为硬伤。
- **易用性有待提升**  ：密态相关命令的导出导入、工具支持、帮助信息等方面仍有优化空间。
- **生态适配需要完善**  ：需与瀚高数据库管理系统V9.0.10版本内核保持同步，支持pg_upgrade升级等。
- **功能完整性需要补全**  ：4.0.0版本中部分功能存在缺失或边界不清晰的问题，如copy导出格式支持、pg_dump导出密钥语句、复杂语法支持等。


因此，需要在V4.0.0版本基础上，研发瀚高全密态数据库V4.0.1版本，在密文计算能力、密钥管理、易用性、生态适配等方面进行增强和完善。

## 2.2   **目标**

瀚高全密态数据库V4.0.1的目标如下：

- **引入同态加密能力**  ：支持密文加(+)、减(-)运算和SUM聚合，支持密文乘(*)运算和幂(^)运算。同态加密支持与DET/OPE/SEARCH/RND并存，也支持单独启用。支持int2_enc/int4_enc/int8_enc三种密态数字类型。
- **支持密钥轮换**  ：实现KEK密钥轮换功能，支持通过ALTER KEK语句更换KEK，对关联DEK进行重新加密。
- **增强4.0.0版本已有功能**  ：包括copy导出支持子查询和binary格式、pg_dump支持导出KEK/DEK创建语句、增强关联/并集/嵌套/GROUP BY等语法支持。
- **提升易用性**  ：完善密态相关命令的导出导入能力、psql元命令支持、参数补全、帮助信息、会话控制等。
- **完善生态适配**  ：基于V9.0.10内核开发，适配V9.0.10需求，支持pg_upgrade从V4.0.0升级。


## 2.3   **产品的特点**

瀚高全密态数据库V4.0.1在继承V4.0.0全部功能的基础上，新增以下核心特点：

- **密文聚合计算能力**  ：引入同态加密算法，支持在密文上直接执行加减运算和SUM聚合，解密结果与明文计算结果一致，实现“密文可计算”。同时支持密文乘法运算。
- **密钥轮换机制**  ：支持通过ALTER KEK语句在线更换密钥加密密钥，对关联的数据加密密钥进行重新加密，无需重建数据库或重加密业务数据，满足等保测评和安全合规要求。
- **灵活的算法组合**  ：同态加密（he-add/he-mul）可通过support_algo参数与DET/OPE/SEARCH/RND灵活组合配置，满足不同业务场景对查询能力和计算能力的需求。
- **增强的生态适配**  ：基于V9.0.10内核开发，支持从V4.0.0通过pg_upgrade平滑升级。


# 3   **假定和约束**

**假定： **

- 瀚高全密态数据库V4.0.1的生命周期与瀚高数据库管理系统V9.0.10产品生命周期保持一致。
- 系统运行环境：Linux x86_64平台及国产化平台（ARM架构）。
- 同态加密功能依赖于非对称密钥体系，其非对称 KEK 支持软加密（localkms）与硬加密（tzwykms/swxakms）；密钥轮换功能支持所有KMS类型（localkms、tzwykms、swxakms）。


**约束：**

- 同态加密仅支持int2_enc、int4_enc、int8_enc三种密态整数类型，不支持numeric_enc、float4_enc、float8_enc。
- he-add列支持密文加(+)、减(-)运算和SUM聚合，以及标量乘法；he-mul列支持密文的乘(*)运算和标量乘法、幂(^)运算（指数为正整数），不支持加减和SUM。
- 仅支持在PG兼容端口使用同态加密功能。


**适用场景：**

- 统计分析类业务：需要对加密数据进行SUM汇总统计的场景，如金融行业交易总额统计、医疗行业用药总量统计等。
- 合规审计场景：需要满足等保测评、安全合规评审中关于密钥轮换要求的场景。
- 数据共享与分析：需要在保护数据隐私的前提下，对多部门数据进行密文聚合分析的场景。

#### 4.4.1.2 同态加密

**需求描述：**

引入同态加密能力，支持在密文上直接执行加减乘运算和SUM聚合，扩展密态数据库在统计分析场景中的应用能力。

同态加密的 HE DEK（he-add/he-mul）绑定非对称 KEK（key_algo='sm2'），该 KEK 支持软加密（localkms）与硬加密（tzwykms/swxakms）两种存储方式，密钥细节见 4.5.1.2。

**说明：**

扩展建表语法，支持同态加密：

```sql
CREATE TABLE 表名 (
    列名 密态类型 ENCRYPTED WITH (加密选项[, 加密选项...]) [列约束],
    ...
);
```

加密选项（以逗号分隔，可组合使用）：
- DEK = 对称DEK名：对称DEK，供DET/OPE/SEARCH算法使用，支持指定模式名：[模式名.DEK名]；列启用任一对称算法时必选；
- SUPPORT_ALGO = '算法列表'：列启用的算法。算法列表除原有的det、ope、search选项之外，新增he-add和he-mul。he-add和he-mul即支持单独配置，也支持与其它算法混合配置，单独配置he-add/he-mul时不启用rnd密文。（不配置SUPPORT_ALGO或仅配置det/ope/search等对称算法时，会同时启用rnd算法）；
- HE_ADD_DEK = 同态加法DEK名：he-add算法使用的同态DEK，支持指定模式名：[模式名.DEK名]，列启用he-add时必选；
- HE_MUL_DEK = 同态乘法DEK名：he-mul算法使用的同态DEK，支持指定模式名：[模式名.DEK名]，列启用he-mul时必选。

**V4.0.1-20-3-1** 密态整数类型支持同态加法（he-add）。密态列在定义时将support_algo参数设置为'he-add'，即可对加密列执行加法（+）、减法（-）运算和SUM聚合。运算直接在密文上进行，无需解密；运算结果解密后与明文直接计算的结果一致。

该特性适用于int2_enc、int4_enc、int8_enc三种密态数据类型，三种类型之间支持跨类型运算（如int2_enc与int4_enc相加），加减法均支持双向组合，结果类型取较大者（如 int2_enc + int4_enc → int4_enc、int2_enc + int8_enc → int8_enc），跨类型运算要求参与列使用同一DEK。

同态加法既支持两个密态列(使用同一DEK)之间的运算，也支持密态列与整型常量的加法、乘法标量运算；运算结果可赋值给仅开启he-add的密态列，不支持赋值给混合配置其它算法的密态列。

SUM聚合的结果类型与原生一致，统一提升为int8：sum(int2_enc) → int8_enc、sum(int4_enc) → int8_enc、sum(int8_enc) → int8_enc。

服务端同态运算时不进行溢出判断，运算结果在客户端解密后按结果类型进行范围校验：超出对应整数类型（int2/int4/int8）的表示范围时报错。

同态加法的运算结果存在明文范围上限：单值读写和单次加法（仅两个操作数）不受限制，明文范围覆盖 int8 全范围；当将多个明文持续累加到同一密文（SUM 聚合、链式加法、连续 UPDATE 赋值等）时，累计明文总和不能超过约 42.9 亿，超出则解密失败。

示例：

```sql
CREATE TABLE t (
    a int4_enc ENCRYPTED WITH (HE_ADD_DEK = dek_add, SUPPORT_ALGO = 'he-add'),
    b int4_enc ENCRYPTED WITH (HE_ADD_DEK = dek_add, SUPPORT_ALGO = 'he-add')
);
INSERT INTO t(a, b) VALUES (10, 5), (20, 7);
SELECT a + b FROM t;    -- 两个密态列相加（同一DEK），解密返回明文
SELECT a - a FROM t;    -- 同列相减，结果为0
SELECT c + d FROM t;    -- 跨类型：c为int2_enc、d为int4_enc，结果类型为int4_enc（同一DEK）
SELECT SUM(a) FROM t;   -- SUM聚合，解密返回30
SELECT a * 3 FROM t;    -- 密态列与整型常量的标量乘法
UPDATE t SET a = a + b; -- 运算结果赋值给其它he-add列（同一DEK），成功
```

> 备注：该需求基于椭圆曲线ElGamal（EC-ElGamal）加法同态算法实现。算法参考：T. ElGamal, "A Public Key Cryptosystem and a Signature Scheme Based on Discrete Logarithms", IEEE Transactions on Information Theory, Vol.31, No.4, 1985；椭圆曲线密码体制参考 N. Koblitz, "Elliptic Curve Cryptosystems", Mathematics of Computation, Vol.48, No.177, 1987。

**V4.0.1-20-3-2** 密态整数类型支持同态乘法（he-mul）。密态列在定义时将support_algo参数设置为'he-mul'，即可对加密列执行乘法（*）和幂运算（^、power）运算。运算直接在密文上进行，无需解密；运算结果解密后与明文直接计算的结果一致。

该特性适用于int2_enc、int4_enc、int8_enc三种密态数据类型，三种类型之间支持跨类型运算（如int2_enc与int4_enc相乘），乘法支持双向组合，结果类型取较大者（如 int2_enc × int4_enc → int4_enc、int4_enc × int8_enc → int8_enc），跨类型运算要求参与列使用同一he-mul DEK。

同态乘法既支持两个密态列之间的运算，也支持密态列与整型常量的标量运算；运算结果可赋值给其它同算法（he-mul）的密态列。

运算结果在客户端解密后按结果类型进行范围校验：结果超出对应整数类型（int2/int4/int8）的表示范围时报错。

幂运算将密文在服务端重复相乘n-1次（a^n = a×a×…×a，即同态乘法叠加），指数n必须为正整数，支持常量或非密态整数列，不支持密态列作为指数；为防范指数过大导致服务端运算耗时失控（DoS），指数上限为10000，超过上限时报错。 (docs: 内置函数适配补充power函数、依赖算法DET改DET/OPE；同态描述分段整理)

示例：

```sql
CREATE TABLE t (
    a int4_enc ENCRYPTED WITH (HE_MUL_DEK = dek_mul, SUPPORT_ALGO = 'he-mul'),
    b int4_enc ENCRYPTED WITH (HE_MUL_DEK = dek_mul, SUPPORT_ALGO = 'he-mul')
);
INSERT INTO t(a, b) VALUES (3, 2), (5, 4);
SELECT a * b FROM t;    -- 两个密态列相乘（同一DEK），解密返回明文
SELECT a * 3 FROM t;    -- 密态列与整型常量的标量乘法
SELECT c * d FROM t;    -- 跨类型：c为int2_enc、d为int4_enc，结果类型为int4_enc（同一DEK）
SELECT a ^ 3 FROM t;    -- 同态幂运算（^运算符）：服务端重复相乘n-1次，解密返回明文（a的3次方）
SELECT power(a, 3) FROM t; -- 同态幂运算（power函数），与 ^ 等价
UPDATE t SET a = a * b; -- 运算结果赋值给其它he-mul列（同一DEK），成功
```

> 备注：该需求基于有限域ElGamal乘法同态算法实现。算法参考：T. ElGamal, "A Public Key Cryptosystem and a Signature Scheme Based on Discrete Logarithms", IEEE Transactions on Information Theory, Vol.31, No.4, 1985。

**V4.0.1-20-3-3** 支持同态加密算法与对称加密算法并存。同一密态列可同时配置同态加密算法（he-add/he-mul）与对称加密算法（DET/OPE/SEARCH/RND），例如support_algo='det,he-add'。此时需要分别为对称算法与同态算法指定DEK：对称DEK（用于DET/OPE/SEARCH/RND）仍用“DEK = ”参数指定，同态DEK分别用HE_ADD_DEK和HE_MUL_DEK可选参数指定。

示例：

```sql
CREATE TABLE t (
    a int4_enc ENCRYPTED WITH (DEK = dek_sym, HE_ADD_DEK = dek_add, SUPPORT_ALGO = 'det,he-add'),  -- 对称与he-add并存
    b int4_enc ENCRYPTED WITH (DEK = dek_sym, SUPPORT_ALGO = 'det'),                               -- 仅对称算法
    c int4_enc ENCRYPTED WITH (HE_ADD_DEK = dek_add, SUPPORT_ALGO = 'he-add'),                    -- 仅he-add
    d int4_enc ENCRYPTED WITH (DEK = dek_sym, HE_ADD_DEK = dek_add, HE_MUL_DEK = dek_mul,         -- 对称+he-add+he-mul全开
                               SUPPORT_ALGO = 'det,he-add,he-mul')
);
INSERT INTO t(a) VALUES (10);   -- 密文含 det槽 + he-add槽
SELECT a FROM t;                -- RND解密返回明文
SELECT a + a FROM t;            -- 同态加法，结果仅含he-add密文
UPDATE t SET c = a + a;         -- 正确：赋给仅he-add列，成功

```

约束：由于DET、RND、OPE、SEARCH等对称加密密文不支持同态运算，对并存列执行加法、减法、乘法运算时，结果密文仅包含he-add或he-mul密文段，其它算法的密文段不被携带。该结果只允许赋值给仅配置he-add或he-mul的密态列；赋值给包含对称算法配置的列（无论仅对称算法，还是对称与同态并存）时，因结果密文缺少对称算法密文段而报错，例如：
```sql
UPDATE t SET b = a + a;         -- 报错：赋给仅对称算法列，结果无det密文
UPDATE t SET a = a + a;         -- 报错：赋给对称+he-add并存列，结果无det密文
UPDATE t SET d = a + a;         -- 报错：赋给对称+he-add+he-mul全开列，结果无det密文
                                -- 错误信息如：cannot assign encrypted value with DEK ... to column ... which uses DEK ...
```

建表时的校验规则：

- SUPPORT_ALGO包含DET/OPE/SEARCH/RND中任一算法时，必须提供对称DEK（DEK参数），且该DEK的key_algo参数必须为'sm4'；
- SUPPORT_ALGO包含he-add时，必须提供he-add DEK（HE_ADD_DEK参数），且其key_algo参数必须为'he-add'；
- SUPPORT_ALGO包含he-mul时，必须提供he-mul DEK（HE_MUL_DEK参数），且其key_algo参数必须为'he-mul'；
- 未配置的算法对应的DEK参数可省略；
- 所有指定的DEK必须存在，且当前用户对其具有使用权限（USAGE），否则报错；
- 同态DEK（he-add/he-mul）必须绑定非对称KEK（key_algo='sm2'），对称DEK绑定对称KEK或非对称KEK均可。

KEK/DEK的创建与使用详见4.5.1节密钥管理。

#### 4.4.1.3 密态视图

**需求描述：**

支持在视图中包含密态列，视图查询时根据客户端密态开关和解密权限返回明文或密文。

**说明：**

**V4.0.1-20-3-4** 标准视图（VIEW）支持包含密态列，视图查询行为与直接查询基表一致：客户端开启密态功能且有权限时返回明文，否则返回密文。

视图创建（CREATE VIEW）语句按普通视图处理，密态列定义无需在视图中重复声明；视图查询（SELECT FROM view）时，前端按视图返回的密态列类型自动解密，解密结果与直接查询基表一致。

支持的视图场景：

- 视图可包含密态列，也可混合包含普通列

- 视图可包含全部或部分密态列（如仅选择部分加密列）

示例（普通视图）：

```sql
-- 前置：创建 KEK/DEK 与含密态列的基表（name 列配置 DET 算法用于等值过滤）
CREATE KEK kek1 WITH (key_store = 'localkms', key_path = '/path/to/kek1.key');
CREATE DEK dek1 WITH VALUES(KEK = 'kek1');
CREATE TABLE employee (
    id     int,
    name   text_enc ENCRYPTED WITH (DEK = dek1, SUPPORT_ALGO = 'DET'),
    salary int4_enc ENCRYPTED WITH (DEK = dek1)
);
INSERT INTO employee VALUES (1, 'Alice', 10000), (2, 'Bob', 20000), (3, 'Charlie', 30000);

-- 创建包含密态列的普通视图：定义中密态列过滤常量由客户端自动加密
CREATE VIEW emp_view AS
    SELECT id, name, salary FROM employee WHERE name = 'Alice';

-- 查询视图：客户端按视图加密列元数据自动解密，与直接查询基表一致
SELECT id, name, salary FROM emp_view;   -- 返回明文：1 | Alice | 10000

-- 视图查询时追加过滤条件（密态列由客户端改写加密）
SELECT id, name FROM emp_view WHERE name = 'Alice';   -- 返回明文：1 | Alice
```

**V4.0.1-20-3-5 支持密态物化视图：**

物化视图支持包含密态列，查询行为与直接查询基表一致。具体说明：

- 物化视图创建（CREATE MATERIALIZED VIEW）支持包含密态列（投影），列类型继承 SELECT 结果类型（\*_enc），数据以密文存储（与基表密文一致，DEK 继承基表列）；
- 物化视图创建时自动注册加密列元数据（hg_encrypted_columns，继承基表列的 DEK 与算法），客户端查询时按元数据自动解密；
- REFRESH MATERIALIZED VIEW 按已存储的定义重新填充密文数据，行为与基表一致；WITH NO DATA / WITH DATA 与 PostgreSQL 原生语义一致；
- 视图/物化视图定义中可对密态列使用等值/范围过滤（=、<>、<、>、<=、>=，需列配置 DET/OPE 算法），前端自动加密常量，行为与直接查询基表一致。

示例（物化视图）：

```sql
-- 沿用上述 employee 基表（含密态列）

-- 创建包含密态列的物化视图：数据以密文落盘，加密列元数据自动继承基表
CREATE MATERIALIZED VIEW emp_mv AS
    SELECT id, name FROM employee WHERE id > 1;

-- 查询物化视图：客户端自动解密，与直接查询基表一致
SELECT id, name FROM emp_mv;   -- 返回明文：2 | Bob，3 | Charlie

-- 基表数据变化后刷新物化视图
INSERT INTO employee VALUES (4, 'David', 40000);
REFRESH MATERIALIZED VIEW emp_mv;
SELECT id, name FROM emp_mv;   -- 返回明文：2 | Bob，3 | Charlie，4 | David

-- WITH NO DATA：仅创建物化视图结构，不填充数据
CREATE MATERIALIZED VIEW emp_mv_empty AS
    SELECT id, name FROM employee WITH NO DATA;
```

 

#### 4.4.1.4 内置函数适配

##### 4.4.1.4.1 内置函数支持

**需求描述：**

验证数据库内置函数的支持情况，对于不支持的内置函数返回固定格式错误信息。

**说明：**

**V4.0.1-20-3-6** 内置函数支持情况：

|函数名|函数功能|密态类型|依赖算法|
|---|---|---|---|
|count|统计行数|全部密态类型|无需算法|
|sum|对密态数值列求和（密文聚合）|int2_enc、int4_enc、int8_enc|HE-ADD|
|min|求最小值|全部密态类型|OPE|
|max|求最大值|全部密态类型|OPE|
|coalesce|返回参数列表中第一个非NULL值|全部密态类型|无需算法|
|nullif|两个参数相等时返回NULL，否则返回第一个参数|全部密态类型|DET/OPE|
|greatest|返回参数列表中的最大值|全部密态类型|OPE|
|least|返回参数列表中的最小值|全部密态类型|OPE|
|case|按条件（WHEN）求值，返回匹配分支的结果|全部密态类型|DET/OPE|
|decode|按等值条件匹配，返回对应分支的结果|全部密态类型|DET/OPE|
|power|密文幂运算（密文重复相乘，a^n）|int2_enc、int4_enc、int8_enc|HE-MUL|

**使用限制：**

- greatest / least：要求所有参与比较的参数（密态列或同类型常量）互相可比较，相关密态列需配置 OPE 算法；密态列仅配置 DET 算法时执行报错（大小比较依赖 OPE）。参数可混合密态列与同类型常量（常量按列算法加密），但不同密态类型之间、密态列与普通数据列之间不支持比较。示例：`GREATEST(salary_ope, 55000)` 正常执行；`GREATEST(salary_det, 55000)`（salary_det 仅配置 DET）报错。
- CASE 的 WHEN 条件引用密态列时，条件常量按列的算法加密；THEN/ELSE 分支可返回密态列（结果解密返回）或普通常量，但各分支返回类型应保持一致（同为密态类型或同为普通类型）。分支返回类型不一致（如密态列与类型不匹配的普通值混用）时，前端无法确定常量的加密方式，返回错误。示例：`CASE WHEN val > 150 THEN val ELSE 0 END`（val 为 OPE 列）正常执行；WHEN 条件中密态列与普通列直接比较、或分支混用无法统一加密的类型时报错。
- coalesce：参数可混合密态列与同类型常量（常量按列算法加密），参数类型需一致。
- power：指数须为正整数，支持常量或非密态整数列，不支持密态列作为指数；为防范指数过大导致服务端运算耗时失控（DoS），指数上限为10000，超过上限时报错；he-add列（无EG_MUL密文段）执行幂运算时报错。

除上述函数外，其它内置函数在密态列上均不支持。

#### 4.4.2.1 工具增强

#### 4.4.2.2 会话控制

**V4.0.1-20-3-11** 新增会话级元命令“\enable hg_tecc.mode / \disable hg_tecc.mode”，用于控制当前已连接会话是否启用 TECC 客户端透明加解密能力。该能力用于调试、验收和运维场景，在不重新建立连接的情况下切换当前会话的明文视图和密文视图。

- 该开关为客户端会话级状态，不是服务端 GUC，不写入 `pg_settings`，不通过 `SET/SHOW/RESET` SQL 命令设置，不持久化到数据库系统表。
- 在 psql 中，用户通过 `\enable hg_tecc.mode` 开启当前连接的 TECC 透明加解密，通过 `\disable hg_tecc.mode` 关闭当前连接的 TECC 透明加解密。
- 在上层 libpq 应用中，用户通过公开接口 `PQteccSetMode(PGconn *conn, int enabled)` 修改当前 `PGconn` 的 TECC 会话模式，通过 `PQteccGetMode(PGconn *conn, int *enabled)` 获取当前模式；接口成功返回 0，失败返回 -1。
- 开启时，libpq 对 SQL 执行密态列识别、常量加密和 SQL 改写，并对查询结果执行客户端解密，应用侧看到明文。
- 关闭时，libpq 跳过 SQL 加密/改写和结果解密；查询普通列或按非密态条件定位记录时，密态列结果以服务端返回的密文格式展示，便于检查密文落盘与传输形态。
- 该开关仅影响当前 `PGconn` 连接，不影响其他连接；连接关闭后状态消失；事务回滚不回滚该客户端状态。
- - 该开关不依赖连接已启用 TECC 能力。可自由切换连接的加解密状态。

## 4.5   **安全性需求**

### 4.5.1   **安全性**

**需求描述：**

本版本新增的密钥管理功能对产品安全架构的影响如下。

**说明：**

#### 4.5.1.1 软加密密钥生成工具（tecc_ktool）

**V4.0.1-20-3-16** 提供tecc_ktool命令行工具，用于生成KEK密钥文件。对称KEK（key_algo = 'sm4'）模式下生成对称密钥，加密后写入.key文件；非对称KEK（key_algo = 'sm2'）模式下生成SM2密钥对，公钥写入.pub文件，私钥加密后写入.priv文件。CREATE KEK时从.priv同目录自动加载.pub文件将公钥入库hg_kek_args。

tecc_ktool的核心定位：离线KEK文件管理工具，不依赖数据库连接，仅管理软加密（localkms）的本地密钥文件，不涉及硬加密（tzwykms/swxakms）密码机；功能及参数如下：

tecc_ktool generate --key-name <name> --key-algo <sm4|sm2> --key-path <目录> [--force]



扫描目录下的.key和.priv文件，展示列表（Name列展示key-name，即文件名去扩展名）

tecc_ktool list [--dir <path>]



查看KEK文件元信息（key_algo、算法、版本、创建时间）

tecc_ktool info --key-path <path>



销毁KEK文件

tecc_ktool delete --key-path <path>



校验KEK文件完整性（HMAC校验）

tecc_ktool validate --key-path <path>



generate文件命名规则：`--key-path` 指定生成目录，文件名由 `--key-name` 决定——sm4生成 `<key-name>.key`，sm2生成 `<key-name>.priv`（私钥）与 `<key-name>.pub`（公钥）。重复校验：目标文件已存在时generate报错拒绝覆盖，防止误覆盖已注册KEK导致关联DEK无法解密；确认需要重新生成时加 `--force` 显式覆盖。list的Name列展示key-name（文件名去扩展名）。info/delete/validate 仍以 `--key-path` 指向具体密钥文件操作。

tecc_ktool与CREATE KEK的分工：tecc_ktool负责线下密钥文件生成，CREATE KEK负责将KEK元数据注册至数据库。两者配合使用——tecc_ktool生成文件后，CREATE KEK引用生成的文件路径（`<目录>/<key-name>.key` 或 `<目录>/<key-name>.priv`）即可。

各工具/功能的边界：tecc_ktool是独立CLI工具，只管localkms的密钥文件管理（对称.key、非对称.priv/.pub，不碰数据库）。ALTER KEK是SQL语句，负责在线DEK重加密（需要数据库连接）。对称KEK（key_algo = 'sm4'）为SM4（KEK是单一对称密钥，加密存.key文件）；非对称KEK（key_algo = 'sm2'）为SM2（KEK是密钥对，私钥加密存.priv文件，公钥入库hg_kek_args）。

#### 4.5.1.2 非对称密钥管理（CREATE KEK / CREATE DEK）

**V4.0.1-20-3-17** CREATE KEK新增key_algo参数，支持两种取值：key_algo = 'sm4'（对称KEK，默认）和key_algo = 'sm2'（非对称SM2 KEK）。对称KEK存盘时加密写入.key文件（路径记录在hg_kek_args的key = 'key_path'中）；非对称KEK的SM2私钥加密写入本地.priv文件（路径记录在hg_kek_args的key = 'key_path'中），公钥在CREATE KEK时从.priv同目录下的.pub文件加载后入库hg_kek_args。密钥文件由tecc_ktool工具生成（见V4.0.1-20-3-16），CREATE KEK引用生成的密钥文件。服务端不存储私钥，不改变”服务端零信任”的安全模型。

**非对称 KEK 公钥与私钥的存储、使用与权限区别：**

- **公钥**：CREATE KEK 时加载入库，服务端统一保存，所有拥有该 KEK USAGE 权限的用户在任意客户端均可使用——用于加密 HE 数据（写能力）与创建 DEK 时的 SM2 信封加密（对 DEK 密钥材料做信封保护）；
- **私钥**：仅创建 KEK 的客户端持有（软加密 localkms 下存本地 .priv 文件，硬加密 tzwykms/swxakms 下存密码机内、永不出境）——用于解密 HE 数据（读能力），且是创建 DEK 的前置条件。

创建 DEK 的私钥校验：非对称 KEK（key_algo = 'sm2'）下，任何 CREATE DEK（传统对称 DEK、同态 HE DEK）均要求所绑 KEK 私钥可用——软加密 localkms 下要求 .priv 文件存在，缺失（被删除/丢失）时 CREATE DEK 报错，禁止创建绑定到私钥不可用 KEK 的 DEK；硬加密 tzwykms/swxakms 下私钥保留在密码机内、永不出境，由密码机连通性保证。因此，创建绑非对称 KEK 的 DEK（含 HE DEK）仅在持有该 KEK 私钥的客户端或接入对应密码机的客户端可完成，其它客户端无法仅凭入库公钥创建 DEK；但已创建的同态 DEK 在任意客户端仍可加密写入 HE 数据（写能力依赖入库公钥，不依赖 KEK 私钥），解密仅限持有私钥的客户端（需手动复制）或接入密码机的客户端。

**CREATE KEK 语法规则：**

```sql
CREATE KEK kek名 [IF NOT EXISTS] [WITH (KEK选项[, KEK选项...])]
```

KEK选项（以逗号分隔）：
- KEY_STORE = 'localkms' | 'tzwykms' | 'swxakms'：密钥存储方式（必选；'hsmkms'为V4.0.0版本同智伟业密码机的旧名称，仅向后兼容保留）；
- KEY_ALGO = 'sm4' | 'sm2'：密钥算法（默认sm4）；
- KEY_PATH：密钥定位（必选，各KMS类型内容不同）。软加密（localkms）下为密钥文件绝对路径（如 '/data/kek.key'），指向tecc_ktool预先生成的密钥文件；硬加密（tzwykms/swxakms）下为密码机密钥索引，格式'hsm:id=<索引>'（如 'hsm:id=1'），指向密码机内存储的KEK。

CREATE KEK语法示例：

- 对称KEK（key_algo = sm4）：`CREATE KEK kek WITH (KEY_STORE = localkms, KEY_ALGO = sm4, KEY_PATH = '/data/kek.key')`

- 非对称KEK（key_algo = sm2）：`CREATE KEK kek WITH (KEY_STORE = localkms, KEY_ALGO = sm2, KEY_PATH = '/data/kek.priv')`

说明：CREATE KEK 通过 KEY_STORE 指定密钥存储方式（localkms 为本地文件，tzwykms 为同智伟业密码机，swxakms 为三未信安密码机；hsmkms 为V4.0.0版本同智伟业密码机的旧名称，仅向后兼容保留），KEY_ALGO 指定密钥算法（sm4/sm2，默认sm4），KEY_PATH 指定密钥定位——软加密（localkms）为密钥文件绝对路径，硬加密（tzwykms/swxakms）为密码机密钥索引'hsm:id=<索引>'。软加密下 KEY_PATH 指向的文件由 tecc_ktool 工具预先生成（见 V4.0.1-20-3-16），CREATE KEK 仅注册元数据并校验文件存在性，不负责生成密钥文件；非对称KEK 的 SM2 公钥在 CREATE KEK 时加载并入库 hg_kek_args——软加密（localkms）下从 KEY_PATH 同目录的 .pub 文件加载，硬加密（tzwykms/swxakms）下从密码机导出公钥（SM2 私钥始终保留在密码机内、不出境）。

CREATE DEK新增key_algo参数，支持以下取值：

- 不指定（默认）：'sm4'对称DEK（DET/OPE/SEARCH/RND）

- key_algo = 'he-add'：加法同态密钥对

- key_algo = 'he-mul'：乘法同态密钥对

同态DEK按算法独立生成密钥对，'he-add'与'he-mul'各是各的，互不混用。

**CREATE DEK 语法规则：**

```sql
CREATE DEK dek名 [IF NOT EXISTS] WITH VALUES (DEK选项[, DEK选项...])
```

DEK选项（以逗号分隔）：
- KEK = KEK名：绑定的KEK（必选）；
- KEY_ALGO = 'sm4' | 'he-add' | 'he-mul'：DEK算法（默认sm4）。

说明：ENCRYPTED_VALUE、HE密钥对（he_ec_pubkey等）等内部参数由系统在CREATE DEK时自动生成、pg_dump导出时自动包含（见4.4.2.1 V4.0.1-20-3-10），用户一般无需指定。

CREATE DEK语法示例：

- 传统SM4-DEK：`CREATE DEK dek WITH VALUES(KEK = kek_sm4)`

- 同态加密DEK（加法）：`CREATE DEK he_add_dek WITH VALUES(KEK = kek_sm2, KEY_ALGO = 'he-add')`

- 同态加密DEK（乘法）：`CREATE DEK he_mul_dek WITH VALUES(KEK = kek_sm2, KEY_ALGO = 'he-mul')`

同态加密DEK的密钥管理：

- HE密钥对生成：创建同态加密DEK时，按key_algo生成对应算法的HE密钥对（'he-add'生成加法同态密钥对，'he-mul'生成乘法同态密钥对），密钥对由公钥和私钥组成。

- 公钥存储与使用：HE公钥明文存储于服务端hg_dek_args表（he-add DEK公钥存key='he_ec_pubkey'，he-mul DEK公钥存key='he_eg_pubkey'），公钥可公开；服务端持公钥即可在同态密文上直接完成加减乘、SUM 聚合等运算，无需私钥。

- 私钥存储与使用：HE私钥用KEK公钥做信封加密后存储于服务端hg_dek_args表（he-add DEK私钥存key='he_ec_privkey'，he-mul DEK私钥存key='he_eg_privkey'），不以明文形式落库；客户端查询时用KEK私钥解信封获取HE私钥（软加密 localkms 下用本地.priv私钥文件解密，硬加密 tzwykms/swxakms 下SM2私钥始终在密码机内、由密码机解密接口解信封），用于解密同态运算结果——服务端不接触私钥明文。

- 约束：同态加密DEK必须绑定非对称KEK（key_algo = 'sm2'）；对称KEK无公钥，无法对HE私钥做信封加密，创建时校验并报错。创建时同时校验所绑KEK私钥可用（软加密localkms要求.priv文件存在，缺失报错，见上文"非对称 KEK 公钥与私钥的存储、使用与权限区别"）。

- 一列多DEK：同一密态列可同时绑定对称DEK（供DET/OPE/SEARCH/RND）与同态DEK（he-add/he-mul按算法独立），各DEK密钥材料独立生成、独立存储；KEK轮换时，各DEK分别用新KEK重新加密。建表时的DEK绑定语法与校验规则见4.4.1.2 V4.0.1-20-3-3。

#### 4.5.1.3 KEK 密钥轮换（ALTER KEK）

**ALTER KEK 语法规则：**

```sql
ALTER KEK kek名 [WITH (KEK选项[, KEK选项...])]
```

ALTER KEK 用于密钥轮换：指定新的KEY_PATH（软加密为tecc_ktool预先生成的新密钥文件路径；硬加密为密码机新密钥索引'hsm:id=<索引>'），数据库自动用新KEK重新加密关联DEK。

**V4.0.1-20-3-18**  新增ALTER KEK语句支持KEK密钥轮换。语法示例：

- 对称KEK（key_algo = sm4，软加密）：`ALTER KEK kek WITH (KEY_PATH = 'new_key.key')`

- 非对称KEK（key_algo = sm2，软加密）：`ALTER KEK kek WITH (KEY_PATH = 'new_kek.priv')`

- 硬加密（tzwykms/swxakms）：`ALTER KEK kek WITH (KEY_PATH = 'hsm:id=<新密钥索引>')`（密码机内新KEK密钥索引）

密钥轮换流程：运维准备新KEK（软加密localkms：用tecc_ktool生成新密钥文件——对称KEK（key_algo = 'sm4'）生成新.key文件、非对称KEK生成新.priv和.pub文件；硬加密tzwykms/swxakms：在密码机中生成新KEK，获取新密钥索引）→ 执行ALTER KEK（软加密指定新KEY_PATH文件路径；硬加密指定新KEY_PATH='hsm:id=<新密钥索引>'），数据库自动用新KEK重新加密关联DEK。软加密（localkms）下，重加密按DEK类型分别处理：对称KEK（key_algo = 'sm4'）下的对称DEK（encrypted_value）用新KEK重加密；非对称KEK（key_algo = 'sm2'）下绑定的对称DEK（encrypted_value信封）与HE DEK私钥信封（he_ec_privkey/he_eg_privkey）均用新KEK公钥重新信封加密。硬加密（tzwykms/swxakms）模式下，KEK始终存储在密码机内部不出境，客户端仅持有密钥索引；DEK密文（对称DEK的encrypted_value、HE DEK的私钥信封he_ec_privkey/he_eg_privkey）仍存储于数据库hg_dek_args，重加密时对称KEK场景由密码机内的对称KEK解密DEK后重加密、非对称KEK场景由密码机内SM2私钥解HE私钥信封再用新KEK公钥重信封，安全模型不变。密钥轮换需进行权限检查，仅KEK所有者或具有相应权限的用户可执行。轮换过程对应用透明，失败时可回滚。ALTER KEK 为在线轮换：轮换期间及完成后不中断其它连接对密态数据的访问（各连接独立缓存、DEK 明文不变、已加密业务数据无需重加密）。软加密（localkms）下，轮换后解密需使用新 KEK 私钥文件：KEK 所有者所在客户端更新本地新私钥文件（.priv）即可继续解密；其它持有私钥的客户端需手动同步新私钥文件（或接入对应密码机），未同步前仅可写不可读。

（`hg_tecc_mode=on` 且当前用户具有相应 DEK 的 `USAGE` 权限时，返回解密后的原始明文字节 hex；`hg_tecc_mode=off` 或没有 DEK 权限时本函数直接报错，不加载解密密钥，也不返回密文或明文 hex。）

**tecc_enc_ratio(table_name text [, varlena_length int])** 返回 `setof record`，用于估算含密态列表的存储膨胀情况。函数按表的列定义和密态列元数据进行静态估算，不扫描表内真实数据，因此适合管理员在建表后、导入数据前或容量规划阶段快速评估密态列带来的存储开销。

参数说明：

|参数|类型|是否必填|说明|
|---|---|---|---|
|table_name|text|是|待估算的表名，支持 `table`、`schema.table` 形式；表名应解析到当前数据库内的一张普通表。|
|varlena_length|int|否|变长类型估算长度，单位为字节，用于 `text`、`varchar`、`bytea`、`numeric` 等未能从 typmod 得到固定长度的明文类型；省略时默认按 20 字节估算，取值必须大于 0。|

返回结果由若干密态列明细行和一行 `TOTAL` 汇总行组成。明细行展示单个密态列相对于原始明文列的膨胀情况，汇总行展示整表在 100 万行数据规模下的估算磁盘占用。

示例（使用默认变长长度 20 字节）：
```sql
SELECT column_name, source_len, plain_size, enc_size, ratio::numeric(12,2) AS ratio
FROM tecc_enc_ratio('tecc_admin_func_table')
WHERE column_name <> 'TOTAL'
ORDER BY column_name;
```

输出示例：

|column_name|source_len|plain_size|enc_size|ratio|
|---|---:|---:|---:|---:|
|c_int|4|4|124|31.00|
|c_txt|20|24|160|6.67|

示例（查看整表 100 万行估算值）：
```sql
SELECT column_name, total_plain_1m, total_enc_1m,
       overall_ratio::numeric(12,2) AS overall_ratio
FROM tecc_enc_ratio('tecc_admin_func_table')
WHERE column_name = 'TOTAL';
```

输出示例：

|column_name|total_plain_1m|total_enc_1m|overall_ratio|
|---|---:|---:|---:|
|TOTAL|84459520|341336064|4.20|

示例（显式指定变长类型按 100 字节估算）：
```sql
SELECT *
FROM tecc_enc_ratio('tecc_admin_func_table', 100);
```

字段含义：

|字段|含义|
|---|---|
|column_name|列名；汇总行为 `TOTAL`。|
|source_type|密态列对应的原始明文类型；汇总行为 NULL。|
|source_len|原始明文数据估算长度，单位为字节；定长类型使用类型固定长度，变长类型优先使用 typmod，无法确定时使用 `varlena_length`。|
|enc_type|密态列类型，如 `int4_enc`、`text_enc`；汇总行为 NULL。|
|algorithms|密态列配置的算法列表，如 `RND`、`RND,OPE`、`RND,DET,SEARCH`；汇总行为 NULL。|
|plain_size|单个明文值的估算存储大小，单位为字节；变长类型包含 varlena 头部。|
|enc_size|单个密文值的估算存储大小，单位为字节，包含密文结构头及已配置算法段的估算长度。|
|ratio|单列膨胀率，计算公式为 `enc_size / plain_size`。|
|total_plain_1m|仅汇总行返回，表示 100 万行普通明文表的估算磁盘占用，单位为字节。|
|total_enc_1m|仅汇总行返回，表示 100 万行密态表的估算磁盘占用，单位为字节。|
|overall_ratio|仅汇总行返回，表示整表膨胀率，计算口径为密态表行大小 / 明文表行大小，包含非密态列及行存储开销。|

估算口径：

- 函数仅统计密态列明细行，但整表汇总会同时考虑非密态列的存储空间，因此 `overall_ratio` 通常小于各密态列单列 `ratio`。
- 密文大小按当前 CipherDataType 结构和密态列配置的算法段估算，默认包含 RND 基础段，并叠加 DET、OPE、SEARCH、HE_ADD、HE_MUL 等已配置算法段。
- 100 万行磁盘占用按 PostgreSQL heap page 结构估算，考虑 tuple header、NULL bitmap、列对齐、行指针和页面头等开销；该值用于容量规划，不等同于真实表文件大小。
- 函数不扫描真实数据，不考虑 TOAST 外置存储、索引、FSM/VM 文件、表膨胀、页碎片、fillfactor 变化和压缩效果。
- 该函数属于密态诊断工具函数。调用用户必须具有目标表的整表 `SELECT` 权限；仅有部分列的 `SELECT` 权限时不能执行。无权限时返回 `permission denied for table`，且不输出密态列配置和容量估算信息。
## 4.7   **测试性需求**

### 4.7.1   **性能指标**

**需求描述：**

在相同环境下，针对不同场景，分别对明文和密文进行性能测试并对比；V4.0.1在V4.0.0既有性能场景上的性能不下降。

**说明：**

**V4.0.1-20-3-20** 沿用V4.0.0性能指标：使用100万条测试数据，同态场景使用独立同态表（两列分别开启he-add和he-mul），与对称加密场景（全量/等值/范围/模糊查询）分开测试，避免同态段干扰对称加密的扫描与查询性能；在相同软件和硬件环境下，使用软加密方式，测试客户端解密场景下的全量查询、等值查询、范围查询、模糊查询、同态加法、同态乘法等场景。每个查询场景执行至少5次，丢弃第一次的结果，取后续次数的平均耗时作为最终结果。确保V4.0.1在上述场景上的性能指标不劣于V4.0.0，具体指标如下：

| 场景 | 返回数据量 | 客户端性能指标(Timing) |
|------|------------|-----------------------------|
| 全量查询 | 全量返回，100万条 | 平均耗时 ≤ 8000ms |
| 等值查询（使用索引） | 返回1行 | 平均耗时 ≤ 120ms |
| 范围查询（使用B树索引） | 返回100行 | 字符类型平均耗时≤ 60ms；数字类型平均耗时≤30ms |
|  | 返回10000行 | 字符类型平均耗时≤ 290ms；数字类型平均耗时≤160ms |
| 模糊查询（前缀匹配） | 返回100行 | 平均耗时≤320ms |
|  | 返回10000行 | 平均耗时≤420ms |
| 同态加法 | 返回10000行（纯解密返回） | 平均耗时≤ 50000ms |
|  | SUM1万行（服务端聚合） | 平均耗时≤ 20000ms |
| 同态乘法 | 返回10000行（纯解密返回） | 平均耗时≤ 30000ms |
|  | 幂运算（a^10000） | 返回1行，平均耗时≤ 300ms |

说明：
1. 同态"返回10000行"用例为纯解密返回（SELECT a，不做加减乘运算），体现客户端解密性能；SUM1万行体现服务端密文聚合+客户端解密一次；幂运算（a^10000）仅服务端重复同态乘法（9999次）、客户端只解密1行结果，体现服务端运算性能。
2. 同态乘法（FF-ElGamal，有限域整数模运算）比同态加法（EC-ElGamal，椭圆曲线点运算）性能更好，原因在于椭圆曲线的点加/标量乘点运算本身包含多次有限域模运算，计算复杂度显著高于同规模的大整数模运算——这是算法本身的特性。
3. 模糊查询采用5字符固定前缀匹配（LIKE '第一数据组%'），测试数据（val_search）由5个5字符前缀（'第一数据组'～'第五数据组'）轮换生成，各占20%；匹配时程序需扫描5倍的行数才能命中足够数据（返回100行需扫描约500行、返回10000行需扫描约50000行），确保模糊匹配具有可量化的扫描工作量，避免命中率过高导致匹配过早结束。示例查询：SELECT val_search FROM enc_text WHERE val_search LIKE '第一数据组%' LIMIT 100;
