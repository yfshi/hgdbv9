# TECC易用性设计

> 状态：部分实现
> 适用版本：TECC 4.0 / PostgreSQL 14 分支  
> 代码范围：psql Tab 补全、psql 帮助、SQL 帮助、TECC 元命令

## 1. 设计目标

本文档中的“易用性”特指 TECC 在 psql 交互环境中的可发现性和可操作性，而不是密态计算主流程本身。目标是让用户在 psql 中通过 Tab、`\?`、`\h` 和元命令即可发现并使用 TECC 新增参数、语法、函数和密钥对象，尽量减少手写系统表查询和记忆复杂 SQL 的成本。

本设计覆盖四类能力：

- psql 中 TECC 参数、函数、密钥对象和元命令支持 Tab 补全。
- 新增 GUC 参数和 TECC 语法在帮助信息中可见。
- psql 支持显示建表、建 KEK、建 DEK 语句。
- psql 元命令支持显示 KEK/DEK 信息，使用方式接近 `\d`、`\df` 等原生命令。

## 2. Tab 补全设计

### 2.1 设计目标

Tab 补全用于降低用户输入 TECC 语法和对象名的记忆成本。用户在 psql 中输入 TECC 关键字、KEK/DEK 名称或 TECC 元命令时，可以通过 Tab 查看候选项。

实现位置：

- `src/bin/psql/tab-complete.c`

核心机制：

- 使用 PostgreSQL psql 既有补全框架。
- 静态关键字通过 `COMPLETE_WITH()` 或命令生成器返回。
- 数据库对象通过 `SchemaQuery` 查询系统表生成。
- TECC 对象补全复用 `hg_kek`、`hg_dek` 系统表。
- `\dkek` / `\ddek` 对已输入双引号的对象名前缀使用专用补全路径，避免 psql 原生 readline 未完整支持双引号标识符补全导致的不稳定体验。

### 2.2 KEK/DEK 对象补全

新增两个 TECC 对象查询：

```c
Query_for_list_of_keks
Query_for_list_of_deks
```

查询来源：

- `pg_catalog.hg_kek`
- `pg_catalog.hg_dek`

支持场景：

| 输入场景 | 补全内容 |
| --- | --- |
| `DROP KEK <Tab>` | KEK 名称 |
| `DROP DEK <Tab>` | DEK 名称 |
| `CREATE DEK ... KEK = <Tab>` | KEK 名称 |
| `\dkek <Tab>` | KEK 名称 |
| `\ddek <Tab>` | DEK 名称 |
| `\dkek "My<Tab>` | 按未加引号前缀 `My` 匹配 KEK，并返回带双引号的候选 |
| `\ddek "My<Tab>` | 按未加引号前缀 `My` 匹配 DEK，并返回带双引号的候选 |
| `\sK <Tab>` | KEK 名称 |
| `\sk <Tab>` | DEK 名称 |

双引号补全说明：

- psql 初始化 readline 时只把单引号加入 `rl_completer_quote_characters`，没有全局开启双引号标识符补全。
- TECC 不修改全局 quote 字符策略，避免影响 psql 其它 SQL 标识符补全行为。
- 对 `\dkek` / `\ddek` 的 pattern 参数，如果当前输入 token 以 `"` 开头，补全逻辑会剥离开头双引号并按原始 KEK/DEK 名称做前缀匹配，然后返回 `"..."` 形式候选；对象名中的 `"` 会按 SQL 标识符规则双写。
- 普通未加引号场景仍复用 `COMPLETE_WITH_SCHEMA_QUERY(Query_for_list_of_keks/deks, NULL)`。

### 2.3 TECC DDL 关键字补全

补全场景：

```sql
CREATE <Tab>
CREATE KEK <Tab>
CREATE DEK <Tab>
DROP <Tab>
DROP KEK <Tab>
DROP DEK <Tab>
```

设计要点：

- `words_after_create` 中加入 `KEK`、`DEK` 相关对象类型。
- `create_command_generator()` 和 `drop_command_generator()` 能返回 TECC 命令。
- `CREATE KEK` 后补全 `WITH`、配置参数等关键字。
- `CREATE DEK` 后补全 `WITH VALUES`、`KEK` 等关键字。

### 2.4 ENCRYPTED WITH 子句补全

目标语法：

```sql
CREATE TABLE t (
    c text_enc ENCRYPTED WITH (DEK = dek1, SUPPORT_ALGO = 'DET')
);
```

补全内容包括：

- `ENCRYPTED`
- `WITH`
- `DEK`
- `SUPPORT_ALGO`
- 可用 DEK 名称
- 算法候选值：`DET`、`OPE`、`SEARCH`

该能力让用户在建表时不必完整记忆 `ENCRYPTED WITH` 的参数拼写。

### 2.5 TECC 函数补全

TECC 工具函数注册到 `pg_proc` 后，psql 原有函数补全路径可以显示函数名。典型函数包括：

- `tecc_get_tabledef(regclass)`
- `tecc_enc_info(anyelement)`
- `tecc_enc_ratio(text)`
- `tecc_enc_ratio(text, int)`
- `tecc_decrypt_raw(anyelement, text)`

用户在 SQL 中输入函数名前缀并按 Tab，可通过 psql 函数补全查询看到候选函数。

## 3. 帮助信息设计

### 3.1 `\?` 中的 TECC 帮助

实现位置：

- `src/bin/psql/help.c`

psql 的 `\?` 和 `psql --help=commands` 在 TECC 专区展示常用入口：

```text
TECC
  Connection parameter: enable_tecc=true|false (env: PGENABLETECC)
  psql option:          -k on|off controls TECC encryption mode
  Session mode:         \enable hg_tecc.mode / \disable hg_tecc.mode / \show hg_tecc.mode
  Syntax help:          \h CREATE KEK, \h CREATE DEK, \h DROP KEK, \h DROP DEK
  Column clause:        ENCRYPTED WITH (DEK = dek_name [, SUPPORT_ALGO = 'DET|OPE|SEARCH'])
```

设计要点：

- `enable_tecc` 是连接级参数，通过 conninfo 或环境变量控制。
- `-k on|off` 是 psql 命令行入口。
- `\enable hg_tecc.mode` / `\disable hg_tecc.mode` / `\show hg_tecc.mode` 是当前已落地的 psql 运行时入口。
- `hg_tecc_mode` 是客户端会话级伪 GUC 的设计目标；当前代码未发现完整 `SET`/`SHOW` 拦截实现，也未在服务端注册真实 GUC。
- `\h` 指向 TECC 新增 SQL 语法。
- `ENCRYPTED WITH` 给出密态列声明的最小可用格式。

### 3.2 会话开关帮助

当前已实现的 psql 元命令：

```text
\enable hg_tecc.mode
\disable hg_tecc.mode
\show hg_tecc.mode
```

设计目标中的客户端会话级伪 GUC：

```sql
SET hg_tecc_mode = on;
SET hg_tecc_mode = off;
SHOW hg_tecc_mode;
```

实现位置：

- psql 元命令：`src/bin/psql/command.c`
- libpq API：`src/interfaces/libpq/tecc_libpq_integration/fe-tecc-integration.c`
- psql 帮助展示：`src/bin/psql/help.c`
- Tab 补全：`src/bin/psql/tab-complete.c`

语义：

- `\enable hg_tecc.mode`：结果集进入 TECC 客户端解密流程。
- `\disable hg_tecc.mode`：结果集跳过 TECC 客户端解密，用于查看原始密文显示。
- `\show hg_tecc.mode`：读取当前连接内存状态，显示 `enabled` 或 `disabled`。

当前落地的 `hg_tecc.mode` 元命令只读写当前 `PGconn` 的客户端状态。`hg_tecc_mode` 若后续实现，应作为客户端伪 GUC，不在服务端注册真实 GUC，也不出现在服务端 `SHOW ALL` 中。

### 3.3 SQL 语法帮助

实现位置：

- `doc/src/sgml/ref/create_kek.sgml`
- `doc/src/sgml/ref/create_dek.sgml`
- `doc/src/sgml/ref/drop_kek.sgml`
- `doc/src/sgml/ref/drop_dek.sgml`
- psql SQL 帮助生成链路：`src/bin/psql/create_help.pl`

用户接口：

```text
\h CREATE KEK
\h CREATE DEK
\h DROP KEK
\h DROP DEK
```

设计要点：

- TECC SQL 命令按 PostgreSQL 原生 SQL 帮助体系提供说明。
- `\h` 输出包含 synopsis、参数说明和示例。
- 用户无需查外部文档即可确认命令格式。

## 4. DDL 显示设计

### 4.1 设计目标

TECC 对象包含额外元数据，例如密态列的 `ENCRYPTED WITH`、KEK 的存储参数、DEK 与 KEK 的绑定关系。原生 `\d` 类命令不能直接输出可回放的创建语句，因此新增专用元命令显示 DDL。

实现位置：

- psql 元命令入口：`src/bin/psql/command.c`
- 帮助展示：`src/bin/psql/help.c`
- 建表 DDL 函数：`src/backend/commands/tecc_tabledef.c`
- 函数注册：`src/include/catalog/pg_proc.dat`

### 4.2 显示 CREATE TABLE

用户接口：

```text
\sT table_name
```

内部查询：

```sql
SELECT pg_catalog.tecc_get_tabledef('table_name'::pg_catalog.regclass) AS ddl;
```

输出内容：

- `CREATE TABLE` 或 `CREATE UNLOGGED TABLE`
- 普通列类型、默认值、非空约束、排序规则
- 密态列的 `ENCRYPTED WITH` 子句
- CHECK 等约束信息

示例输出：

```sql
CREATE TABLE public.account (
    id integer,
    name text_enc ENCRYPTED WITH (dek = dek1, algo = 'DET,SEARCH')
);
```

### 4.3 显示 CREATE KEK

用户接口：

```text
\sK kek_name
```

内部读取：

- `pg_catalog.hg_kek`
- `pg_catalog.hg_kek_args`
- `pg_catalog.pg_namespace`

输出内容：

```sql
CREATE KEK public.kek1 WITH (key_store = 'localkms', key_path = '/tmp/kek1.key');
```

设计要点：

- 过滤内部参数，例如以下划线开头的内部字段。
- 输出 schema-qualified 名称，避免 search_path 不同时回放到错误 schema。

### 4.4 显示 CREATE DEK

用户接口：

```text
\sk dek_name
```

内部读取：

- `pg_catalog.hg_dek`
- `pg_catalog.hg_dek_args`
- `pg_catalog.hg_kek`
- `pg_catalog.pg_namespace`

输出内容：

```sql
CREATE DEK public.dek1 WITH VALUES(KEK = public.kek1);
```

设计要点：

- 输出 DEK 与 KEK 的绑定关系。
- 过滤 `encrypted_value`、`_tecc_processed` 等不应回放的内部字段。

## 5. KEK/DEK 信息显示元命令

### 5.1 设计目标

TECC 密钥对象应像表、函数、类型一样可以在 psql 中查看。新增元命令提供类似 `\d`、`\df` 的对象列表体验，用户无需记忆 `hg_kek`、`hg_dek`、`hg_*_args` 的系统表结构。

实现位置：

- 元命令调度：`src/bin/psql/command.c`
- 查询构造：`src/bin/psql/describe.c`
- 函数声明：`src/bin/psql/describe.h`
- 帮助展示：`src/bin/psql/help.c`
- Tab 补全：`src/bin/psql/tab-complete.c`

### 5.2 `\dkek` 查看 KEK

用户接口：

```text
\dkek[+] [PATTERN]
```

显示字段：

| 普通模式 | 详细模式 `+` |
| --- | --- |
| Schema | Schema |
| Name | Name |
| Owner | Owner |
| Key store | Key store |
| Key path | Key path |
|  | OID |
|  | Created |

内部读取：

- `pg_catalog.hg_kek`
- `pg_catalog.hg_kek_args`
- `pg_catalog.pg_namespace`

能力说明：

- 支持 pattern 过滤。
- 支持 `+` 显示 OID 和创建时间。
- 支持 Tab 补全 KEK 名称。

### 5.3 `\ddek` 查看 DEK

用户接口：

```text
\ddek[+] [PATTERN]
```

显示字段：

| 普通模式 | 详细模式 `+` |
| --- | --- |
| Schema | Schema |
| Name | Name |
| Owner | Owner |
| KEK | KEK |
| Distributed ID | Distributed ID |
|  | OID |
|  | Created |

内部读取：

- `pg_catalog.hg_dek`
- `pg_catalog.hg_kek`
- `pg_catalog.pg_namespace`

能力说明：

- 支持 pattern 过滤。
- 支持 `+` 显示 OID 和创建时间。
- 支持 Tab 补全 DEK 名称。
- 显示 DEK 绑定的 KEK，便于快速确认密钥链路。

## 7. 设计边界

- Tab 补全只提供常用语法和对象候选，不保证覆盖所有合法 SQL 组合。
- `hg_tecc.mode` 是当前 psql 元命令使用的开关名；`hg_tecc_mode` 是客户端伪 GUC 设计目标，当前不出现在服务端 `SHOW ALL` 中。
- `\sK`、`\sk` 输出用于辅助回放和审查，内部密钥密文材料不会作为普通可读字段展示。
- `\dkek`、`\ddek` 只展示密钥对象元信息，不负责执行权限授权或密钥材料解密。

## 8. 测试建议

- `psql --help=commands` 输出包含 TECC 专区和 `\enable hg_tecc.mode` / `\disable hg_tecc.mode` / `\show hg_tecc.mode` 用法。
- `\?` 输出包含 `\dkek`、`\ddek`、`\sK`、`\sk`、`\sT`。
- `\h CREATE KEK`、`\h CREATE DEK`、`\h DROP KEK`、`\h DROP DEK` 能输出语法帮助。
- `CREATE DEK ... KEK = <Tab>` 能补全已有 KEK。
- `DROP KEK <Tab>`、`DROP DEK <Tab>` 能补全已有对象。
- `\show <Tab>` 能补全 `hg_tecc.mode`。
- `\dkek "My<Tab>`、`\ddek "My<Tab>` 能补全包含大写、空格等需要双引号引用的 KEK/DEK 名称。
- `\dkek+`、`\ddek+` 输出详细字段。
- `\sT` 输出带 `ENCRYPTED WITH` 的建表语句。
